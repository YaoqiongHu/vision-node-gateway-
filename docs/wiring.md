# 硬件接线总表

> **这份文档是接线的唯一依据**：改接线先改这里，再改代码。
> 引脚复用能力按 RM0090（STM32F407 参考手册）与 STM32F407 数据手册逐条核对过；
> 板子排针编号见 [`board.md`](board.md)，计划与验收见 [`../project.md`](../project.md)。

## 0. 系统总览

```
                        ┌──────────────────────────────┐
   OV7670 ──── 11 根 ───│                              │
   (DCMI + SCCB)        │        STM32F407ZGT6         │──── UART1 ────> Pi5（图像链路）
                        │          节点（node/）        │     PA9/PA10      2 Mbps
   MPU6050 ─── 2 根 ────│        （SCCB 共用一条总线）  │
                        │                              │──── CAN1 ─────> TJA1050 ──CANH/L──> MCP2515
                        └──────────────┬───────────────┘    PD0/PD1         │
                                       │                                    │
                                  SWD（PA13/PA14）                    ┌─────┴──────┐
                                       │                             │   Pi5      │
                                  ST-Link                            │ （网关）    │
                                                                     └────────────┘
```

两条总线各有分工：**元数据走 CAN 500 kbps**（TJA1050 ↔ MCP2515），**图像走 UART**（2 Mbps 裸线）。
节点与网关**只共 GND，不共电源**。

## 1. 供电与电平

| 器件 | 供电 | IO 电平 | 说明 |
|---|---|---|---|
| F407 开发板 | USB 5V（板上 AMS1117 转 3V3）**或** ST-Link 的 3V3 —— **二选一** | 3.3 V | 两种电源同时接会互相倒灌 |
| OV7670 模块 | **3.3 V** | 3.3 V | **严禁接 5 V**；模块无晶振，XCLK 由 MCU 送 |
| MPU6050 模块 | **3.3 V** | 3.3 V | 模块多带 LDO，接 5 V 也能活，但没必要 |
| TJA1050 | **5 V** | 5 V | 见 §5 的电平说明 |
| MCP2515 模块 | 见 §7（**5 V 还是 3.3 V 必须先确认**） | 5 V 或 3.3 V | Pi 的 GPIO **不耐 5 V**，这是本项目最容易烧板子的一处 |
| Pi5 | 官方 5 V 电源 | 3.3 V | — |

**三条铁律**

1. **只共地，不共电源**。Pi5 用自己电源，F407 用 USB/ST-Link，两者之间只连一根 GND。
2. **所有 3.3 V 器件的 VCC 不许接 5 V**（OV7670、MPU6050 首当其冲）。
3. **Pi5 的 GPIO 只接 3.3 V 电平**。接 5 V 器件的 SPI 之前先确认电压，见 §7。

> **排针只有一个 3V3 脚（J3-57），但 OV7670 和 MPU6050 都要用。**
> 建议拿一块面包板做中转：把 J3-57 的 3V3 和 J3-58 的 GND 引到面包板电源轨，
> 各模块的电源都从轨道取。信号线仍然直连，不要绕面包板（尤其 D0–D7）。

|---|---|---|---|

## 3. OV7670 接线

### 3.1 模块丝印对照

不同厂家的丝印不一样，按功能对齐：

| 模块丝印可能写成 | 接到 |
|---|---|
| `VCC` / `3V3` / `5V`（模块带 LDO 时） | **F407 的 3.3 V**（不要用 5 V） |
| `GND` / `GND1` | GND |
| `SCL` / `SIOC` / `SCK` | PB10 |
| `SDA` / `SIOD` | PB11 |
| `PCLK` / `PCLK0` | PA6 |
| `HREF` / `HSYNC` | PA4 |
| `VSYNC` / `VSYNC0` | PB7 |
| `XCLK` / `XVCLK` / `MCLK` | **PA8**（MCO1，HSE 8 MHz） |
| `D0`–`D7` / `D0`–`D7` | PC6 / PC7 / PC8 / PC9 / PC11 / PD3 / PB8 / PB9 |
| `PWDN` / `PWD` | PE0（暂可接 GND） |
| `RESET` / `RST` | PE1（暂可接 3.3 V） |

### 3.2 一根一根列出来

| # | OV7670 | F407 | 排针 | 说明 |
|---|---|---|---|---|
| 1 | VCC | 3.3V | J3-57 | **严禁 5V** |
| 2 | GND | GND | J3-58 | |
| 3 | SCL/SIOC | PB10 | J2-54 | 与 MPU6050 共用，带上拉 |
| 4 | SDA/SIOD | PB11 | J2-53 | 同上 |
| 5 | XCLK | PA8 | J3-33 | MCO1 输出 8 MHz，模块无晶振 |
| 6 | PCLK | PA6 | J2-29 | |
| 7 | HREF | PA4 | J2-27 | |
| 8 | VSYNC | PB7 | J3-3 | |
| 9 | D0 | PC6 | J3-37 | |
| 10 | D1 | PC7 | J3-36 | |
| 11 | D2 | PC8 | J3-35 | |
| 12 | D3 | PC9 | J3-34 | |
| 13 | D4 | PC11 | J3-24 | |
| 14 | D5 | PD3 | J3-19 | |
| 15 | D6 | PB8 | J3-2 | |
| 16 | D7 | PB9 | J3-1 | |
| 17 | PWDN | PE0 | J2-2 | **高电平 = 掉电**。阶段测试可直接接 GND |
| 18 | RESET | PE1 | J2-1 | 低有效。阶段测试可直接接 3.3 V |

> **PWDN/RESET 的两种接法**
> - **省事（S2/S3 阶段）**：PWDN→GND、RESET→3.3V，写死成"永远工作"。
> - **正式（推荐）**：接到 PE0/PE1，代码可以断电复位传感器 —— 排查"配置写不进去"时一键恢复。
>   现在代码里还没用到这两个脚，接死也不影响。

### 3.3 布线注意事项

- **D0–D7 要尽量短**（PCLK 8–16 MHz，杜邦线太长会串扰，图像出雪花/错位）
- 杜邦线不要和其他信号**平行长距离并排**，中间最好隔一根 GND
- 先把 **PCLK/VSYNC/HREF** 接好能测出波形，再补数据线 —— 出问题时能分层定位

## 4. MPU6050 接线

| # | MPU6050 | F407 | 排针 | 说明 |
|---|---|---|---|---|
| 1 | VCC | 3.3V | J3-57 | 模块带 LDO，但接 3.3 V 最稳 |
| 2 | GND | GND | J3-58 | |
| 3 | SCL | PB10 | J2-54 | **和 OV7670 同一条总线** |
| 4 | SDA | PB11 | J2-53 | 同上 |
| 5 | AD0 | GND | — | 地址 = **0x68**（接 3.3 V 则 0x69） |
| 6 | INT | **不接** | — | PE0 已分给 OV7670 的 PWDN；S14 走轮询 |

### 为什么和 OV7670 共用一条总线

原来计划书里写的是"MPU6050 单独用 I2C2"，实际实现时改成**共用 PB10/PB11**，理由：

1. **地址不冲突**：OV7670 = 0x21，MPU6050 = 0x68，扫描时一眼能分清谁在不在。
2. **引脚不够**：DCMI 已经吃掉 11 个脚，再开一条 I²C 要多占 2 个，收益为零。
3. **软件 I²C 本来就是标准 I²C**：SCCB 只是"从机在第 9 位不拉低"，我们的驱动读 ACK 位、
   MPU6050 要求 ACK —— 两者在同一条总线上互不干扰，因为**同一时刻只有一个从机被寻址**。
4. **风险可控**：真出问题，`bsp_i2c_scan()` 一次就能看出是 0x21 没了还是 0x68 没了。

> 唯一要记住的：SCCB 的"读"是**两次传输**（写地址 + STOP + START + 读），
> MPU6050 也支持这种写法，所以同一个 `read_reg` 逻辑能通吃。

## 5. CAN 收发器（节点侧，TJA1050）

TJA1050 是 8 脚 SOP：

| TJA1050 脚 | 名称 | 接到 |
|---|---|---|
| 1 | TXD | **F407 PD1（CAN1_TX）** |
| 2 | GND | GND |
| 3 | VCC | **5 V**（J3-59） |
| 4 | RXD | **F407 PD0（CAN1_RX）** |
| 5 | Vref | 不接（留空） |
| 6 | CANL | 总线 CANL |
| 7 | CANH | 总线 CANH |
| 8 | S | **GND**（高速模式；接高电平进待机） |

### 5.1 先认出你手上的是哪种形态

| 形态 | 外观 | 怎么接 |
|---|---|---|
| **TJA1050 模块** | 小块 PCB，一侧 `VCC/GND/TXD/RXD`，另一侧 `CANH/CANL`（有的带 `S` 脚） | 杜邦线直连，最省事 |
| **TJA1050 裸芯片** | 8 脚 SOP 贴片 | 要 SOP8 转 DIP 板 + 面包板，得焊 |

F407 这一侧**必须有独立的收发器**；Pi5 那一侧的 MCP2515 模块**可能已经集成了 TJA1050**，判断方法见 §7.1。

### 电平说明（重要）

- TJA1050 **只能用 5 V 供电**，它的 RXD 输出是 **5 V 推挽**。
- F407 的 **PD0 是 FT（5 V 容忍）引脚**，直接接不会烧。
- 反过来，TJA1050 的 TXD 输入阈值是 `VIH ≥ 2.0 V`，**3.3 V 驱动完全够**，不需要电平转换。
- 所以这一路**可以直连**，是本项目少数几个"5 V 和 3.3 V 混接但安全"的地方。

## 6. UART 链路（F407 ↔ Pi5）

| F407 | Pi5 40-pin | Pi5 信号 | 说明 |
|---|---|---|---|
| PA9 (TX) | **pin 10** | GPIO15 / RXD | **交叉** |
| PA10 (RX) | **pin 8** | GPIO14 / TXD | **交叉** |
| GND | **pin 6** | GND | **必须共地** |

- 两端都是 3.3 V TTL，**不需要电平转换**。
- Pi5 侧对应 `/dev/ttyAMA0`（UART0）。要在 `config.txt` 里 `enable_uart=1`，
  并且**关掉串口控制台**（`console=serial0` 那行删掉），否则内核会往里打日志。
- **2 Mbps 对杜邦线是个考验**：线长控制在 **20 cm 以内**，尽量双绞（信号 + 相邻 GND），
  否则误码率会上去。S8 调通之前先用 115200 验证链路，再提速。

## 7. Pi5 侧：MCP2515 模块

### 7.1 先确认电平（最容易烧 Pi 的地方）

MCP2515 模块常见两种：

| 类型 | 特征 | 用法 |
|---|---|---|
| **3.3 V 版** | VCC 接 3.3 V，板上无 LDO 或可跳线 | **首选**，直接接 Pi |
| **5 V 版** | VCC 接 5 V（TJA1050 需要 5 V），SPI 引脚也是 5 V | **必须加电平转换**，否则 Pi 的 GPIO 会被 5 V 打坏 |

判断方法：给模块接 5 V，用万用表量 `CS/SI/SCK` 这几个脚在空闲时是不是 5 V —— 是的话就是 5 V 版。

- **5 V 版的正确接法**：模块 VCC=5 V，SPI 四根 + INT 全部经一个 **3.3↔5 V 双向电平转换模块**（几块钱）。
- **临时替代**：串一个 1 kΩ 电阻到 Pi 的输入脚只能"凑合"，**不可靠，别长期用**。

### 7.2 接线

| MCP2515 模块 | Pi5 40-pin | Pi5 信号 |
|---|---|---|
| VCC | pin 1（3.3 V 版）或 pin 2/4（5 V 版） | — |
| GND | pin 6 | GND |
| CS | **pin 24** | GPIO8 / CE0 |
| SO (MISO) | **pin 21** | GPIO9 / MISO0 |
| SI (MOSI) | **pin 19** | GPIO10 / MOSI0 |
| SCK | **pin 23** | GPIO11 / SCLK0 |
| INT | **pin 22** | GPIO25 |
| RST | 悬空或接 3.3 V | — |

### 7.3 设备树与验证

```ini
# /boot/firmware/config.txt 末尾 —— 8 MHz 晶振是硬约束，写错 can0 起不来
dtoverlay=mcp2515-can0,oscillator=8000000,interrupt=25
```

```bash
sudo reboot
dmesg | grep -i mcp2515            # 应看到 mcp2515 注册成功
sudo ip link set can0 up type can bitrate 500000
ip -details link show can0         # 确认 bitrate 500000、state ERROR-ACTIVE
```

## 8. CAN 总线本身

```
   TJA1050 (节点)                                    MCP2515 模块 (Pi5)
   ┌────────┐                                        ┌────────────┐
   │ CANH 7 ├────────────────────────────────────────┤ CANH       │
   │ CANL 6 ├────────────────────────────────────────┤ CANL       │
   └────────┘                                        └────────────┘
        │                                                   │
      120 Ω                                               120 Ω
        │                                                   │
       GND ──────────────── 共地 ──────────────────────── GND
 ```

- **两端各一个 120 Ω**，并联成 60 Ω（CAN 标准要求）。MCP2515 模块上通常自带一个带跳线的 120 Ω，跳上就行。
- 只用短线实验时，**一个 120 Ω 也能跑**，但长时间/高速下必须两端都有。
- CANH/CANL 最好**双绞**；短线（< 50 cm）用杜邦线可以，但别把两根线拆得太开。
- 上电后用 `candump` 前先确认：**两端 GND 相通**、**终端电阻 60 Ω 左右**（断电用万用表量 CANH-CANL）。

### 8.1 接完线先做静态检查（断电状态下）

| 检查 | 期望值 | 不对说明什么 |
|---|---|---|
| CANH–CANL 之间电阻 | **60 Ω 左右**（两端各 120 Ω 并联） | ∞ = 终端电阻没接上；0 Ω = 总线短路 |
| TJA1050 的 `S` 脚对 GND | **0 Ω** | 悬空或接高 = 待机模式，总线上完全没波形 |
| F407 的 GND ↔ Pi5 的 GND | 导通 | 不共地必然乱码 |
| 5V 对 GND | 不短路 | 本项目踩过一次 3V3-GND 短接 |

### 8.2 上电后的三步验证

1. 量 TJA1050 的 `RXD`：空闲时应为**高**（总线 recessive）。一直低 = 总线被拉死或收发器坏。
2. Pi5 上运行 `sudo ip link set can0 up type can bitrate 500000`，再用 `ip -details link show can0` 确认 `state ERROR-ACTIVE`。
3. 这时 F407 若还在跑"芯片内部回环自测"，`candump can0` 是空的 —— **正常**。要看到报文，固件必须切到正常模式发送。

## 9. 上电顺序与自检清单

### 上电顺序

1. 先接好 **GND**，再接信号线。
2. 确认所有 3.3 V 器件（OV7670、MPU6050）的 VCC **没有接到 5 V**。
3. 最后上电：先给 F407，再给 Pi5，最后给 CAN 总线（如果收发器单独供电）。

### 分阶段自检（每步都能单独定位）

| 阶段 | 检查 | 通过标准 |
|---|---|---|
| S1 | LED0/LED1 闪、串口打印 | 串口看到 `SYSCLK = 168 MHz` |
| S2-1 | 逻辑分析仪夹 **PA8** | 8 MHz 方波 |
| S2-2 | 串口 `[sccb] OV7670 PID=0x76 VER=0x73` | OK |
| S2-3 | CAN1 loopback 自测 | 自发自收，无错误 |
| S3 | 逻辑分析仪夹 **PA6（PCLK）** | 有连续时钟；VSYNC 约 10 Hz |
| S3 | 读回 `OV7670_REG_COM7` | 等于写入值 |
| S4 | DCMI + DMA 抓一帧 | 图像不错位、帧率达标 |

> **排查口诀**：先量电源和地，再量时钟，最后才怀疑数据线。
> 每加一根线，就做一次自检 —— 一次只引入一个变量。

## 10. 已知的坑（踩过的）

| 现象 | 原因 | 处理 |
|---|---|---|
| SCCB 扫描全空、`PID=0xFF` | **SCL/SDA 接反** | 对调两根线（本项目真踩过） |
| SCCB 扫描全空、但线没接反 | PWDN 被拉高（芯片掉电） | 量 PWDN，必须 0 V |
| XCLK 测出来不是 8 MHz | 逻辑分析仪采样率太低 | 采样率 ≥ 10 倍被测频率 |
| CAN 完全没波形 | 位定时算错 / 收发器没供电 / STB 脚没接地 | 先 loopback 自测，再查 TJA1050 的 S 脚 |
| Pi5 上 `can0` 起不来 | overlay 的 `oscillator` 写成 16 MHz | 必须 `8000000` |
| 图像出雪花/错位 | D0–D7 杜邦线太长 | 缩短到 10 cm 以内，远离其他信号 |
| 串口 2 Mbps 丢字节 | 杜邦线太长 / 没共地 | 缩短、双绞、先共地 |
